· Context & problem statement

Problem 1. Voice/STT model lists were hardcoded in the client at client/src/data/providerOptions.ts — 8 voices, 1 STT model. Meanwhile Deepgram's /v1/models exposes 102 TTS voices and 408 STT entries with rich metadata (preview WAV, accent, avatar, streaming flags, use-case tags). Users couldn't see what Deepgram actually offers; new voices required a code change.

Problem 2. Cost/usage was computed locally in server/app/services/pricing.py from Pipecat metrics × a hardcoded rate table. Deepgram now returns authoritative USD per request via GET /v1/projects/{id}/requests/{id} (response.details.usd) — verified against the live account.

Non-goals for this slice. No provider registry. No ElevenLabs, Sarvam. No LLM-usage reconciliation (Google doesn't return per-call USD). Hindi TTS deliberately deferred — Deepgram has 0 Hindi voices; that's the future trigger to add Sarvam.

Runtime voice-allowlist → regex (required follow-up)

The initial Piece 1 patch shipped the wider dynamic catalog to the UI, but the runtime at server/app/services/pipecat_adk_runtime.py still hard-rejected any voice not in an 8-item allowlist (SUPPORTED_DEEPGRAM_VOICES) — which would have blocked 45 of the 53 dynamic voices at synthesis time.

Fix: replaced the allowlist with a canonical-shape regex. Deepgram itself rejects truly invalid names at the wire; the runtime only needs to accept the pattern.

DEEPGRAM_VOICE_PATTERN = re.compile(r"^aura(?:-2)?-[a-z0-9]+-[a-z]{2}(?:-[a-z]{2})?$")

# in _deepgram_voice_model():
if DEEPGRAM_VOICE_PATTERN.match(voice):
    return voice
raise RuntimeError(f"Unsupported Deepgram voice: {voice}")

server/tests/test_voice_runtime.py also gained an assertion for aura-2-selene-en — a voice outside the old allowlist, to lock in that the wider catalog is accepted.

Why "STT models" have categories

The STT dropdown now shows 14 entries — same architecture family (Nova), 14 different domain-tuned variants:

  • Nova 3 General / Medical — newest, multilingual (16 languages including Hindi in one model).
  • Nova 2 domain-specific — General, ConversationalAI, Phonecall, Meeting, Voicemail, Video, Medical, Finance, Automotive, Drivethru, ATC, EA. Each trained on audio + vocabulary from that vertical.

Why they differ: a model trained on drive-thru orders learns "McFlurry" but mangles "electrocardiogram". A phone-tuned model knows narrowband 8kHz audio codec artifacts. Automotive is trained with road noise. Default choice for a general voice agent: Nova 3 General.

2 Deepgram-authoritative analytics

Replace locally-computed USD (from a hardcoded rate table × Pipecat metrics) with the actual USD Deepgram reports per request. Keep TTFB local — Deepgram doesn't expose client-perceived latency.

The two API discoveries that made this possible

1. Every Deepgram streaming session gets a single dg-request-id assigned during the WebSocket handshake. STT surfaces it inside TranscriptionFrame.result.metadata.request_id. TTS returns it in the WS handshake response headers.

2. GET /v1/projects/{id}/requests/{id} (auth: usage:read scope) returns response.details.usd — the settled dollar cost. Settlement lag observed: seconds, not minutes.

End-to-end flow

1Session startsUser opens the test call panel
2STT request ID capturedFirst TranscriptionFrame → provider.request_id trace event (kind=stt)
3TTS request ID capturedTTS on_connected handler reads dg-request-id header → trace event (kind=tts)
4Session endsWebSocket finally block fires asyncio.create_task(schedule_reconciliation(run_id))
5Wait 30 sLet Deepgram settle the request (Pending → Success)
6Fetch each request_idGET /v1/projects/{id}/requests/{request_id} with management key
7Parse + persistAppend provider.usage trace events with usd, duration_s, characters
8Reports re-readspricing.session_totals prefers authoritative USD; UI shows "Deepgram-reported" badge

STT capture — the exact hook

# in UserTranscriptBridge.process_frame(...)
is_transcript = isinstance(frame, (TranscriptionFrame, InterimTranscriptionFrame))
if is_transcript and not self._stt_request_id_captured:
    request_id = _extract_deepgram_request_id(getattr(frame, "result", None))
    if request_id:
        self._stt_request_id_captured = True
        await self._record_trace(
            "provider.request_id",
            {"provider": "deepgram", "kind": "stt", "request_id": request_id},
        )

Failure modes & fallback behavior

  • Missing management key or project_id → reconciliation logs and returns 0. Runs still show locally-computed cost.
  • Deepgram management API 5xx / network fail → per-request fetch is wrapped in try/except; other request_ids still get reconciled.
  • Request still Pending (no usd yet) → we skip it. Next reconciliation cycle can pick it up.
  • Already reconciled → _load_state reads existing provider.usage events and skips those IDs. Safe to re-run.
  • Catalog fetch fails → bundled JSON is returned; console warning; UI dropdowns still populated with the 8+4 fallback options.
